# Edge KD + NAS — Assignment 4 (Edge Computing & Intelligent Systems)

Original implementation of the two-part assignment:

- **Q1 — Knowledge distillation.** A ResNet-50 teacher trained on CIFAR-100 distils its logits and
  intermediate features into MobileNetV2, SqueezeNet and EfficientNet-Lite0 students. Includes
  baseline (hard-label only) training, temperature-scaled soft targets, feature hints, unified
  PyTorch/ONNX Runtime inference, and CPU benchmarking.
- **Q2 — Hardware-aware NAS.** An Optuna TPE search over a searchable CNN space on CIFAR-10 that
  measures **real CPU latency, model size and peak memory**, rejects architectures that violate
  deployment constraints, retrains the winner from scratch and exports it to ONNX.

Hugging Face is used throughout for dataset sourcing (`datasets`), device/AMP orchestration
(`accelerate`), model backbones via `timm`, and optional checkpoint upload (`huggingface_hub`).

> **Academic integrity:** all code in this repository is written from scratch for this submission.
> Third-party architectures and libraries are cited in [`docs/report.md`](docs/report.md). No code
> was copied from other student submissions.

## Layout

```
configs/        teacher.yaml, student.yaml, nas.yaml  (every hyper-parameter)
src/
  data.py       CIFAR loaders backed by HF datasets, cached to .npz
  engine.py     seed, AMP helpers, train/eval loops, CSV + checkpoint IO
  models/       timm backbone factory + feature-hook wrapper
  kd/           soft-target, hard-label and feature distillation losses
  nas/          search space, architecture builder, HW profiler, Optuna search
  deploy/       ONNX export (with parity check) and unified runtime
  hf/           HF dataset/accelerate/Hub helpers
scripts/        one entry point per pipeline stage
checkpoints/    <run>/best.pt
onnx/           <run>.onnx + <run>.json
results/        training logs, summaries, NAS history, benchmark.csv
docs/           report.md, report.pdf, screenshots/ (result plots)
```

The technical report is provided as both Markdown and PDF; the figures under
`docs/screenshots/` are generated by `scripts/make_screenshots.py` and embedded in the PDF by
`scripts/make_report_pdf.py`. For classroom submission, the deliverables are zipped as
`22i-2147_A.zip`.

## Installation

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

The first run downloads CIFAR-10/100 through `datasets` (`uoft-cs/cifar10`, `uoft-cs/cifar100`)
and caches them under `data/`. Set `EC_DATA_DIR` to move that cache.

## Pipeline

Every stage is configurable with `--config` and `--set key=value`.

```bash
# Q1
python scripts/train_teacher.py --config configs/teacher.yaml
python scripts/train_student.py --config configs/student.yaml --mode baseline
python scripts/train_student.py --config configs/student.yaml --mode kd
python scripts/summarize.py

# Q2 — run locally on the GPU for speed; profiling itself is always CPU
python scripts/nas_search.py --config configs/nas.yaml
python scripts/nas_retrain.py --config configs/nas.yaml

# Deployment + benchmarking
python scripts/export_onnx.py
python scripts/infer.py --model checkpoints/kd_mbv2/best.pt --image path/to/img.png
python scripts/benchmark.py
```

The shipped Q1 configs train on the full CIFAR-100 split for 10 epochs; the NAS config uses a
5,000-image CIFAR-10 subset and 6 trials so the search finishes quickly on a consumer GPU
(e.g. RTX 2060 6 GB). Raise `epochs`, `n_trials` or `max_train` for a longer run — the code path
is identical.

## Hugging Face

`src/hf/pipelines.py` exposes:

- `load_hf_cifar(name)` — HF `datasets` loader with a numpy cache;
- `AccelerateRunner` — `accelerate.Accelerator` wrapper for mixed precision / device placement;
- `push_checkpoint_to_hub(...)` — optional upload when `HF_TOKEN` and `EC_HF_REPO` are set.

No HF account is required for local training. Training on HF infrastructure can be done by
running the same scripts in a Spaces/Jobs container with the repo mounted.
